# Epicare Project — Document Index

Master index. `01-Instructions` and `02-Knowledge-Base` are **common** and sit at the project root. All other documents are stored **by month**: each month folder has the same structure and its own `MONTH-INDEX.md` with the full history of that month. **Last updated:** 2026-10-28 (generated by `scripts/build_index.py`).

## How to look something up
1. Read the instruction files in `01-Instructions` (always, for every requirement).
2. Look for the topic in the **Requirement lookup** table below (title and keywords).
3. If it exists, open only that month's `MONTH-INDEX.md` and the documents it links to. Don't search the other months or folders.
4. If it doesn't exist, it's a new requirement: use the next free numbers below and file it in the current month's folder (`python scripts/new_doc.py REQ "<title>"` creates the month folder the first time).

## Naming and numbering
`<PREFIX>-<3-digit serial>_<Short-Title-With-Hyphens>.md`. Serial numbers run across all months and are never reused.

| Folder | Prefix | What goes in it | Next free number |
|---|---|---|---|
| `02-Knowledge-Base` (root, common) | `KB-` | Background: overview, process, integrations, environment, users, guides | KB-001 |
| `YYYY-MM/03-Requirements` | `REQ-` | One per requirement | REQ-001 |
| `YYYY-MM/04-Change-Records` | `CR-` | One per change made to an org | CR-001 |
| `YYYY-MM/05-Conflicts` | `CON-` | Problems, clashes, open risks | CON-003 |
| `YYYY-MM/06-Deployment` | `DEP-` | Only when something is actually deployed to production | DEP-001 |
| `YYYY-MM/07-Technical` | `TECH-` | Technical design and component detail | TECH-001 |
| `YYYY-MM/08-QA/01-Automated-Testing` | `ATR-` | Automated test reports | ATR-001 |
| `YYYY-MM/08-QA/02-Manual-Testing` | `MTC-` | Manual test cases, with `MTC-###_screenshots/` | MTC-001 |
