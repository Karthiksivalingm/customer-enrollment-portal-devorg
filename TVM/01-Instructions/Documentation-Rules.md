# Documentation Rules

## 1. Routing: which event goes where

| Event | Folder | Action |
|---|---|---|
| New task, requirement, enhancement, defect or change request | `03-Requirements/` | `python scripts/new_doc.py REQ "<title>"` and fill it in |
| Requirement changes | `03-Requirements/` | Update the same REQ; add a History row; keep the original request text |
| Actual business-record or configuration-data change in the org | `04-Change-Records/` | `new_doc.py CR "<title>"` with verified before/after values |
| New, changed or removed Salesforce metadata | `07-Technical-Documents/` | Update the topic document, add a dated row to `Change-History.md` (inventories regenerate automatically) |
| Material change to behaviour, architecture, dependencies, data model or security | `02-Knowledge-Base/` | Update the relevant page and its History table |
| Technical error, conflict or unexpected behaviour | `05-Conflicts/` | `new_doc.py CF "<title>"`; keep the original evidence when resolving |
| Deployment preparation, validation, execution or verification | `06-Deployment/` | `new_doc.py DEP "<title>"` and the standing checklists |
| Change to a standing rule or to automation behaviour | `01-Instructions/` | Update the rule and its History / Decisions table |

One event can need several folders (a deployed fix: REQ + CF + DEP + 07-Technical-Documents). Do not create entries in folders that do not apply.
**Metadata retrieval is not a record change and not a deployment.** It is logged only in `07-Technical-Documents/Change-History.md`.

## 2. Dated records

- Name: `YYYY-MM-DD-<TYPE>-<NNN>-<slug>.md`, for example `03-Requirements/2026-10-14-REQ-001-case-routing.md`.
  Types: `REQ`, `CR`, `CF`, `DEP`. Templates: [`config/templates/`](../config/templates/).
- The date is the actual event date (local time zone). Timestamps inside records include the time zone.
- IDs are allocated by `scripts/new_doc.py` (next free number per type). They are never reused; a cancelled item keeps its number
  with status *Cancelled*.
- **No duplicates:** `new_doc.py` returns the existing record when the same `--key` (or the same type, date and title) already exists.
  Use `--key` with a stable event key, for example `--key cr-case-500xx-status-2026-10-14`.
- Front matter (`id`, `date`, `title`, `status`) must match the filename. `scripts/autocommit.py` checks this.
- Records are updated, never silently rewritten. Add a row to the History table for each update, and keep the original evidence.
- Every record links to its related REQ / CR / CF / DEP / 07-Technical-Documents documents.

## 3. Evidence rules

- **Record changes (CR):** before and after values come from queries run before and after the change. A Git diff or a metadata
  retrieval does not prove that a record changed. For bulk changes, record the authorized scope, the counts (selected, succeeded,
  failed), validation results and sanitized evidence. Do not paste full data extracts or unnecessary personal data.
- **Conflicts (CF):** separate *suspected* causes from the *confirmed* root cause. Never mark resolved without verification.
- **Deployments (DEP):** preparation, approval, execution and verification each have their own status. A plan is not an approval.
- **Never fabricate** dates, values, approvals, IDs or results. Write **TO BE CONFIRMED** and say what is needed.

## 4. Technical documents (`07-Technical-Documents/`)

- Topic folders (`Apex-Classes/`, `Flows/`, `Objects-and-Fields/` …) hold hand-written explanations: purpose, entry points,
  dependencies, behaviour, security, tests and verification. Use stable filenames, one per component or per functional area
  (for example `Apex-Classes/CaseTriggerHandler.md`). Each has a History table.
- `Metadata-Inventory/` is generated by `scripts/build_inventory.py` from source. Never edit it by hand.
- `Change-History.md` gets one dated row per created, changed or removed component (or one `[bulk: <manifest>]` row for a bulk
  retrieval). The auto-commit refuses source changes without a matching row.
- Link to the source file. Do not copy whole source files into documents.

## 5. Knowledge Base (`02-Knowledge-Base/`)

Built only from verified Fullsandbox metadata, TVM source and authorized requirements. Mark assumptions and incomplete coverage
clearly (`ASSUMPTION:`, `NOT YET VERIFIED:`). Update the History table at the bottom of each page.

## 6. Index

`DOCUMENT-INDEX.md` is generated by `scripts/build_index.py` and rebuilt on every automatic commit.
