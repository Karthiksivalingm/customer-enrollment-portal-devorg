# Documentation Rules

## 1. Routing: which event goes where

| Event | Folder | Action |
|---|---|---|
| New task, requirement, enhancement, defect or change request | `03-Requirements/` | `node scripts/new-doc.js REQ "<title>"` and fill it in |
| Requirement changes | `03-Requirements/` | Update the same REQ; add a History row; keep the original request text |
| Actual, explicitly authorized business-record or configuration-data change | `04-Change-Records/` | `node scripts/new-doc.js CR "<title>"` with verified before/after values |
| New, changed or removed Salesforce metadata | `07-Technical-Documents/` | Update the topic document and add a dated row to `Change-History.md`; rebuild the inventory |
| Material change to behaviour, architecture, dependencies, data model or security | `02-Knowledge-Base/` | Update the relevant page and its History table |
| Error, conflicting requirement, metadata difference or failed operation | `05-Conflicts/` | `node scripts/new-doc.js CF "<title>"`; keep the original evidence when resolving |
| Deployment preparation, validation, execution or verification | `06-Deployment/` | `node scripts/new-doc.js DEP "<title>"`, the standing checklists and a row in `Deployment-History.md` |
| Change to a standing rule | `01-Instructions/` | Update the rule and its History / Decisions table; update `README.md` and `CLAUDE.md` if needed |

One event can need several folders (a deployed fix: REQ + CF + DEP + 07-Technical-Documents). Do not create entries in folders that do not apply.
**Metadata retrieval is not a record change and not a deployment.** It is logged in `07-Technical-Documents/Change-History.md`
and in a retrieval report under `07-Technical-Documents/Retrieval/`.

## 2. Dated records

- Name: `YYYY-MM-DD-<TYPE>-<NNN>-<slug>.md`, for example `03-Requirements/2026-10-15-REQ-001-case-intake.md`.
  Types: `REQ`, `CR`, `CF`, `DEP`. Templates: [`config/templates/`](../config/templates/).
- The date is the actual event date (local time zone). Timestamps inside records include the time zone.
- IDs are allocated by `scripts/new-doc.js` (next free number per type) and never reused. A cancelled item keeps its number with
  status *Cancelled*. `--key <event-key>` prevents duplicates.
- Front matter (`id`, `date`, `title`, `status`) must match the filename.
- Records are updated, never silently rewritten. Add a History row for each update and keep the original evidence.
- Every record links to its related REQ / CR / CF / DEP / technical documents.

## 3. Evidence rules

- **Record changes (CR):** only when the user explicitly authorized the change. Before and after values come from queries run before
  and after the change. A Git diff or a metadata retrieval does not prove a record changed. For bulk changes record the scope, counts
  (selected, succeeded, failed) and sanitized evidence; no full data extracts or unnecessary personal data.
- **Conflicts (CF):** separate *suspected* causes from the *confirmed* root cause. Never mark resolved without verification.
- **Deployments (DEP):** preparation, approval, execution and verification each have their own status. A plan is not an approval.
- **Never fabricate** dates, values, approvals, IDs or results. Write **TO BE CONFIRMED** and say what is needed.
- Never create a record for an operation that did not happen.

## 4. Technical documents (`07-Technical-Documents/`)

- Topic documents hold hand-written explanations: purpose, entry points, dependencies, behaviour, security and verification.
  Link to the source file; do not copy whole source files into documents. Template: [`config/templates/TECH-component.md`](../config/templates/TECH-component.md).
- `Metadata-Inventory.md` is generated by `node scripts/build-inventory.js` from the local source. Do not edit it by hand.
- `Change-History.md` gets one dated row per created, changed or removed component, or one row per bulk retrieval.

## 5. Knowledge Base (`02-Knowledge-Base/`)

Built only from verified Arizona sandbox metadata, Arizona source and authorized requirements. Label anything else:
`VERIFIED:` (seen in metadata or a query), `INFERRED:` (a reasonable reading of names or structure, not confirmed), or
`OPEN QUESTION:` (needs the business or an administrator). Update the History table at the bottom of each page.

## 6. Index

`DOCUMENT-INDEX.md` lists every document. Update it when a document is added, renamed or removed
(`node scripts/build-inventory.js` regenerates it together with the inventory).
